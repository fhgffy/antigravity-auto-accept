# 原生桌面验收

用于修改扫描路径、审批识别、输入保护、所有权或生命周期后的真实验收。纯文档修改无需启动桌面。以下路径和命令按仓库根目录执行。

## 测试边界

- 使用 F 盘本轮独占目录、独立 IDE 配置和扩展目录，先冻结源码与原包 SHA。登记根 PID、父 PID、创建时间、可执行路径、配置目录和 HWND。2026-10-24：隔离性能环境须锁定扩展版本，测量前后核对实际激活扩展的路径与运行文件字节，不能只核准备包。
- 动作、采样和收尾都重新核对身份；句柄消失或 PID 退出先退休旧记录，再登记新实例。不能拼接不同进程的内存曲线或重启前后的时长。
- 测试过程中不修改用户日常 IDE 的安装、信任或审批设置，不操作未登记窗口及未保存内容（2026-10-27：这条约束测试，不限制插件代用户点击的批准）。只读观察失败不等于产品退出。
- Chrome 默认使用自己启动的独立配置、CDP 和回环页；用户明确授权 Computer Use 浏览器时，只新建本轮测试标签并记录实际配置归属，不把已有配置的新标签说成独立实例，不接管用户已有标签。

## 执行顺序

1. 读取当前验收需求与 `.agent/skills/self-improvement/references/lessons.md` 索引，检查 Git 状态；对故障先记录原始失败。
2. 使用正式包建立基线；带长会话、空闲和最小化窗口分别记录 UIA 元素数、窗口状态和源版本。
3. 每张真实卡记录窗口身份、完整 RuntimeId、精确目标的 UTF-8 SHA、出现时间范围及唯一成功事件；通用 Submit 文案不能证明目标归属。
4. 修改后跑完整回归与 VSIX 字节校验，再跑需要的原生单窗、多任务、双向接管、最小化、待批 Stop/Restart/关闭重开和输入场景。
5. 长测使用单调时钟与独立只读采样器，按 PID/创建时间计算单核 CPU、私有内存斜率、句柄及子进程。说明预热、刷新、缺样和观测时段；GC 堆平稳不代表私有内存平稳。
6. 审批延迟的起点由扫描器之外的观察器取得，保留最后阴性/首次阳性时间及查询间隙，不能使用扫描器首次发现时间代替卡片出现时间。
7. 正常关闭登记的测试窗口，核对确切后代退出；先按原字节归档扩展日志，再按真实路径白名单清理本轮配置。报告实际清理方式，不把回收站当作空间已释放。

## 命令和方法

在独占工作区执行项目已有入口，完整输出保存到本轮测试根目录：

```powershell
npm test
npm run package
$manifest = Get-Content package.json -Raw | ConvertFrom-Json
& ./tests/validate-vsix.ps1 -VsixPath "$($manifest.name)-$($manifest.version).vsix"
```

Windows PowerShell 5.1 读取含中文的无 BOM 脚本时，使用项目现有 UTF-8/AST 引导，不依赖默认 ANSI 解码；记录实际引擎版本。显式调用所需 `powershell.exe`/`pwsh.exe`，不能仅凭工具的 shell 参数认定引擎。2026-10-24：PS7 启动 WinPS5 测试子进程时，仅为该子进程设置对应引擎的原生 `PSModulePath`，避免继承 PS7 模块目录，并核对实际模块解析与退出；不修改父进程或全局环境。

每次动作前取得新 UIA 树，按已观察控件身份定位；不要从 RuntimeId 的某个整数猜 HWND。最小化 Chromium 的树可能收缩或保留旧状态，结合恢复后的新树、真实截图及 READY/退出日志判断所有者。

## 已遇到的坑

- 比较鼠标前先统一坐标空间；DPI 感知的动作回执可能是物理坐标，WinForms 哨兵则是逻辑坐标。用 PhysicalToLogicalPointForPerMonitorDPI 按同一窗口核对，保留原始两套数值，不能忽略不一致的观测。
- PowerShell 构造嵌套 INPUT 值类型时逐层赋回，并检查虚拟键、结构大小及真实 GetAsyncKeyState；给嵌套属性赋值可能只改副本。长按测试必须限时并在 finally 释放。
- PrintWindow 可能返回空白图片；文件存在、模型回复标记及 Agent response 都不能冒充工具原始 stdout。
- Chromium ValuePattern 可保留已删草稿，必须结合 TextPattern/截图；仅能清除与本轮发送文本完全相同的草稿。2026-10-24：空输入可能同时返回换行；结合两个原始值去空白后的结果判断空草稿，不用单一精确空串判断，也不删除未知文本。 同日实测 SetValue 可能只改变可访问性值而未更新实际发送草稿；对已确认属于本轮的文本使用真实输入，并在发送前及发送后的用户消息中读回，不以 SetValue 成功当作发送内容正确。
- 两个真实窗口的 WAITING/ON 要以新树、互斥与生命周期日志交叉核对，不能由旧状态栏文字断定双 owner。
- 2026-10-24：读取仍在写入的日志时，须显式以 ReadWrite/Delete 共享方式只读获取，并验证读取前后长度稳定；共享冲突或不稳定须保留原失败，不能判作产品指标失败。 静态场景日志应区分审批、接管等事件与源码确认的零候选诊断，不能仅因正常诊断使日志变长就判定活动；未知增量仍失败并留证。
- CacheRequest 的 RawView 与原查询可返回不同集合，实测会多出 Restore；性能比较先对齐视图、目标集合和属性读取数量。2026-10-24：查询与 parent walker 须使用同一 UIA 视图，在同布局对照中核对完整目标集合不变，不能仅凭查询变快认定行为等价。新增诊断字段须与原语义契约分开核对；分析器误拒绝时保留原件、原失败和字段来源，只修正明确的 schema 问题，并用完整属性负例复核，不变更性能阈值。
- 缓存仅用于发现候选；动作前仍要取得 live 元素并复核 RuntimeId、目标、宿主、输入和前台。缓存变快不等于审批语义等价。
- 系统输入动作只能用登记测试窗口；普通键、鼠标、修饰键、遮挡与切窗边界不得通过放宽阈值让回归变绿。
- 2026-10-24：后台审批实验先开启扫描器，再把自有哨兵置前台；状态栏切换、UIA 展开或输入聚焦可能改变前台。分开记录根窗口、同进程渲染子窗口和其他应用；用实际前台、空输入端点、原成功日志及变化采样区间核验，不把低频或仅变化记录当成连续无遗漏证明。
- 比较性能时固定窗口布局和并行观察器；整轮耗时减半不代表扫描器 CPU 减半。2026-10-24：重开后重新核对物理矩形，不能仅凭配置认为布局相同。准备脚本明确退出后，用间隔固定的两份完整快照核对 Win32/UIA 几何及全部语义，再开始计数；不一致则停止，不循环刷到绿，测前后检查仍保留。探针若每轮用 Process.Refresh 读取自身私有内存，会把全系统进程信息查询算进自身 CPU；先测空操作开销，再用原生当前进程计数或外部采样拆分。
- 状态记录来自 CIM CreationDate 时，用同一 API 回读创建身份；.NET Process.StartTime 的精度不同，不能逐 tick 混比后误报进程被替换，也不能因此放宽身份检查。2026-10-24：PowerShell JSON 回读可自动将 ISO 日期转成 DateTime；创建时间键须统一规范格式，不能将隐式本地化字符串与 ISO 字符串比较后把既有进程误标为新增。保留原始记录并单独重算误分类，不能更改原采样。
- Chromium 可把工具结果也展平到 Agent response 父节点。应由实际工具步骤展开后出现的命令/原始输出及截图共同判断；单看父节点名称或模型复述均不足。
- 2026-10-24：工具记录按钮须按新树中的实际 Pattern 调用；外层验证脚本也设 Stop，不能在动作报错后继续把模型摘要算作 stdout。WinPS5 解析 JSON 数组先直接赋值再枚举，避免外层 @() 保留嵌套数组后误把整树当单控件；展开前后用新 RuntimeId 与精确输出同时核验。
- 将初始化移到互斥接管之后，必须同时检查宿主协议和启动截止时间；WAITING 免超时仅适用于等锁，拿锁后的重型初始化仍需有界恢复。用真实宿主入口覆盖分段/重复协议、READY、停止卸载和旧实例事件。
- 初始化块跨多个函数时，移动闭括号后立即解析完整 AST，并用冷等待回归确认 UIA 和审批函数均在拿到锁后初始化；字符串锚点存在不证明作用域正确。
