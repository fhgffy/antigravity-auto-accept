# 项目有效经验索引

先按当前任务加载对应项目技能；历史流水仅按需检索，不作为当前环境或版本已通过的依据。

## 桌面与资源

- [原生桌面验收](../../native-desktop-acceptance/SKILL.md)：独占配置、进程身份、真实卡片、输入保护、窗口接管、资源/延迟采样及白名单收尾。
- 每张成功事件应对应窗口、完整卡片身份和精确目标；通用按钮文案、模型自述和空白截图不足以证明真实工具输出。
- 最小化 UIA 树与旧状态栏文字可能失真；恢复后的新树、真实日志和互斥状态分层核对。
- GC 堆稳定不代表私有内存稳定；按进程创建身份分段，不拼接刷新/重启前后的数据。性能探针也要量化自身开销。
- 查询耗时下降与实际单核 CPU 分开验收；固定布局做匹配对照，剩余开销按原函数拆分，不从只读探针的百分比外推产品改善。
- CacheRequest 先对齐 ControlView/目标集合；RawView 实测会多出普通按钮。缓存发现不能替代动作前的 live 身份、目标和输入复核。

## 测试与 CI

- 诊断的编译、进程启动和系统取证开销分层计量；多次有界收集不能共用不足的外层预算。拆成独立案例时保留原单例期限、断言和失败，不能借拆分放过超时。 取证器自身冷启动也超时时，可在被测子进程开始前按原编译期限准备独立工具，显式传入并记录来源哈希；这只增强现场采集，不证明原故障已修复。
- 短命进程退出后 PID 可被复用；观察身份不符时绝不操作新进程。只有本例结果已发布才能结束观察，最终仍核对原持有 Process 的退出及原结果，保留竞争现场。
- 多磁盘证据先将本例文件复制到同一独占上传根，不能把整个临时目录或无关内容作为兜底。安全软件拦截的原型应撤回，不能关防护、改权限或用编码隐藏。
- 生命周期阶段迁移必须联合检查宿主超时协议；等待锁的免超时不能让接管初始化失去恢复。跨模块回归用真实宿主入口和完整扫描器协议各自复现。
- 保留首次失败及原始两流；未定位的空输出超时不能倒推为桌面、网络或编译器问题。
- 失败可能发生在后续夹具创建之前；取证和上传必须覆盖实际失败阶段。先固定原超时为失败，再有界采集同一持有子进程，不能先杀掉目标后才尝试转储。
- 失败诊断也必须有独立短时限和回收；跨位数转储用核对目标 PID、路径及创建时间的 64 位收集器，采集失败后仍由原持有者停止目标并抛原异常，保留下层错误码。循环 finally 的记录失败也须独立捕获，原失败优先；没有原失败时，记录失败本身仍判失败。
- PowerShell 脚本/cmdlet 的成功与原生程序退出码分开判断；脚本返回后核对 $? 和明确完成标记，不能把内部原生探测遗留的 $LASTEXITCODE 当作脚本失败。 Console 直接输出不进入 PowerShell 管道，旁证应从原进程两流或明确文件读取，不能以空管道误判实际动作。
- 重定向 stdout/stderr 要在 WaitForExit 前同时异步排空；严格保留原超时、退出码、stderr、完成标记和同一 Process 的退出确认。
- 获取子进程资源后若身份记录写入失败，持有该 Process 的观察函数负责有限收尾，诊断不能覆盖原异常。刚启动时模块列表可能未就绪；预期路径明确标为预期，动作前再以实际映像严格核对。
- Windows 临时目录短名与 .NET 展开路径要先规范化，再作严格异常断言；不要用忽略路径或放宽断言代替修复。
- 无 BOM 中文脚本用显式 UTF-8/AST 引导；记录实际引擎版本，工具 shell 字段不是引擎版本证明。Python 文本验证器在 Windows 使用 `-X utf8`，不要为默认 GBK 误报转换项目文件。
- PowerShell ScriptProperty 异常可能表现为 null；先读取一次并拒绝 null/0，再转换或据缺失 key 清状态。
- 有序字典按键访问或先 JSON 回读为对象；显示投影为空不代表原始回执丢失。

## 发布与维护

- [三渠道发布核对](../../three-channel-publication/SKILL.md)：同次 main 原包、不可变版本、现有凭据、本人验证码及实际公开下载 SHA。
- 测试、CI、文档维护不单独发版；本轮运行修复合成一个用户可感知版本。审核接收不计公开完成。
- 缺商店凭据的绿色 CI 不证明商店上线；不创建凭据、不扩大权限、不重复上传审核中版本。
- README/CODEX 保持用户说明和一屏状态；run ID、资产 ID、原始哈希及完整诊断只放 verification 文档或测试根目录。
- 修改前保留 Git 状态和原编码；原工作区已有改动先备份核对，再按明确授权整合，不覆盖同事修改。
- 当前目标成功完成回执与随后无当前目标的查询分开判断，不因后者为空重新启动已完成目标。
