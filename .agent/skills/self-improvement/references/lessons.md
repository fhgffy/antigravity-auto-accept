# 项目有效经验索引

先按当前任务加载对应项目技能；历史流水仅按需检索，不作为当前环境或版本已通过的依据。

## 桌面与资源

- [原生桌面验收](../../native-desktop-acceptance/SKILL.md)：独占配置、进程身份、真实卡片、输入保护、窗口接管、资源/延迟采样及白名单收尾。
- 每张成功事件应对应窗口、完整卡片身份和精确目标；通用按钮文案、模型自述和空白截图不足以证明真实工具输出。
- 最小化 UIA 树与旧状态栏文字可能失真；恢复后的新树、真实日志和互斥状态分层核对。
- GC 堆稳定不代表私有内存稳定；按进程创建身份分段，不拼接刷新/重启前后的数据。性能探针也要量化自身开销。
- 查询耗时下降与实际单核 CPU 分开验收；固定布局做匹配对照，剩余开销按原函数拆分，不从只读探针的百分比外推产品改善。
- CacheRequest 先对齐 ControlView/目标集合；RawView 实测会多出普通按钮。缓存发现不能替代动作前的 live 身份、目标和输入复核。

## 测试与 CI

- 诊断的编译、进程启动和系统取证开销分层计量；多次有界收集不能共用不足的外层预算。拆成独立案例时保留原单例期限、断言和失败，不能借拆分放过超时。 取证器自身冷启动也超时时，可在被测子进程开始前按原编译期限准备独立工具，显式传入并记录来源哈希；这只增强现场采集，不证明原故障已修复。
- 共享系统映像的兜底回收须持有同一 Process 句柄并核对创建时间字符串；缺失/错误身份要拒绝，不能用浮点数传递 .NET ticks。
- CIM发现到打开句柄之间可能正常退出；只在原异常类别且有界复查确认PID消失时记为退出竞争，查询失败或PID仍存在继续报错。原测试成功不能被该竞争改成失败；失败后的校准准备留在原测试之后，保留失败和取消语义。
- 短命进程退出后 PID 可被复用；观察身份不符时绝不操作新进程。只有本例结果已发布才能结束观察，最终仍核对原持有 Process 的退出及原结果，保留竞争现场。
- Windows长路径归档失败保留原ZIP及哈希，改短的F盘数字ID目录并记录名称映射；CRC和安全成员校验仍须完整完成，不把部分解压计作验证。
- 多磁盘证据先将本例文件复制到同一独占上传根，不能把整个临时目录或无关内容作为兜底。安全软件拦截的原型应撤回，不能关防护、改权限或用编码隐藏。
- 生命周期阶段迁移必须联合检查宿主超时协议；等待锁的免超时不能让接管初始化失去恢复。跨模块回归用真实宿主入口和完整扫描器协议各自复现。
- 保留首次失败及原始两流；未定位的空输出超时不能倒推为桌面、网络或编译器问题。
- 失败可能发生在后续夹具创建之前；取证和上传必须覆盖实际失败阶段。先固定原超时为失败，再有界采集同一持有子进程，不能先杀掉目标后才尝试转储。 在有界转储可能得不到文件时，可先复用独立只读脚本栈，读取失败也不能跳过原转储与持有者收尾。
- 失败诊断也必须有独立短时限和回收；跨位数取证核对目标 PID、路径及创建时间；能写 DMP 不等于上下文可读，x86 分析还须同位数控制、SystemInfo 架构和实际读栈验证。采集失败后仍由原持有者停止目标并抛原异常，保留下层错误码。循环 finally 的记录失败也须独立捕获，原失败优先；没有原失败时，记录失败本身仍判失败。
- PowerShell 脚本/cmdlet 的成功与原生程序退出码分开判断；脚本返回后核对 $? 和明确完成标记，不能把内部原生探测遗留的 $LASTEXITCODE 当作脚本失败。 Console 直接输出不进入 PowerShell 管道，旁证应从原进程两流或明确文件读取，不能以空管道误判实际动作。
- 重定向 stdout/stderr 要在 WaitForExit 前同时异步排空；严格保留原超时、退出码、stderr、完成标记和同一 Process 的退出确认。
- 获取子进程资源后若身份记录写入失败，持有该 Process 的观察函数负责有限收尾，诊断不能覆盖原异常。刚启动时模块列表可能未就绪；预期路径明确标为预期，动作前再以实际映像严格核对。 旁路观察异常先记录并继续原测试，不能抢停原 Node；两流/结果落盘故障也必须让原退出失败优先。
- Windows 临时目录短名与 .NET 展开路径要先规范化，再作严格异常断言；不要用忽略路径或放宽断言代替修复。
- 有界收集结束后的首次报告命令仍可能冷加载模块；固定回执用无命令模块的编码时必须验证字符串转义及字段类型。读栈旁路也不能为快照加载目标模块；只读内部接口限诊断，按实际引擎验证且缺失即报错。
- 远程读栈会在目标出现PSRP协商线程，不能把观察引入的工作当成原冷启动根因；覆盖前置失败可用默认关闭的云端原生ETW，唯一实例收尾、原失败产物优先上传、独立短预算。仪器样本和可写ETL不能冒充无仪器稳定性或事件可读。 ETW变长栈须按FrameCount/专用InstructionPointer逐帧读取，通用PayloadNames前四槽不能当完整栈，短栈也需拒绝多余槽。
- ETW线程时间须按进程创建身份、栈根及具体线程筛选；READIED_BY包含别的进程，线程退出边界和并行时间不能混算墙钟。硬缺页按文件和区间并集分析，事件丢失/符号缺失/实验性重建边界须保留。
- 纯规则自测不应编译无关桌面依赖；迁移原生断言要保留原输入、真实生产方法调用、明确分项计数，并以单守卫变异证明覆盖没有丢失，不能靠减小计数或预热掩盖原超时。
- 最小备用dump也可能停在同一系统库；必要时先用独立kernel32寄存器旁证，核对线程归属、同位数布局和对齐，finally只恢复本次暂停层数，原失败/预算和原owner回收不变。
- Framework csc默认CSC.RSP会隐式读取整套程序集；独立测试工具显式/noconfig及必需引用，保留真实源/平台/期限，以自有响应文件污染的实际编译控制验证。WOF系统文件冷IO须从原期限内实际线程栈确认，不把其它进程/后置校准或仪器开销外推成产品根因。
- 原生调用前可能仍有库/导出加载；阶段边界只能按实际进入/返回记录解释，不将 handles-ready 等同已进入 API 内部。系统错误码须在旁证 IO 前保存；原始返回节点应先落盘再做断言，API 成功不等于已识别已知控制关系。
- 完整CI样本联合核对两引擎及打包，单边界重复不能计数。普通CI与完整矩阵复用同提交的唯一步骤来源；矩阵产物按样本隔离，默认空后缀须保持正常发布契约，发布仍留在原main-only外层。
- YAML 可解析不等于 Actions 配置有效；用语义检查核对表达式上下文。runner.temp 不能放 job 级 env，应在支持 runner 的实际步骤求值；独立 lint 工作流避免主工作流无效时失去检查。新手动工作流须先在默认分支注册；合并前验收可复用已注册入口的显式默认关闭选项，不先合并未验收内容来取得入口。
- 动态runs-on表达式会让静态检查失去Windows默认shell推断；Windows脚本应显式声明原pwsh。无ShellCheck的本地语义门不覆盖实际语言派发，须保留真实云lint和红绿派发对照，不能关检查来修复误判。
- 云端聚合状态与作业列表可能不同步；用最终Jobs REST及原日志联合确认。官方Actions结果处理事故期间保留原run，不将延迟当源码失败或重跑掩盖；映像对照核对实际OS/Image，而非只信请求标签。
- 网络单请求预算要小于诊断作业总预算；保留审计及必需下载失败检查，用实际npm版本和独占配置/缓存做回环对照，先排空请求体，服务异常不能算产品复现。
- 步骤标题不证明脚本或 npm 已启动；结合自有入口标记和 npm 日志定位静默取消，不能只按总耗时归因网络。生成含 here-string 的脚本避免同层嵌套 here-string，用原编码文件或正确转义的字面量保存。
- 无 BOM 中文脚本用显式 UTF-8/AST 引导；记录实际引擎版本，工具 shell 字段不是引擎版本证明。Python 文本验证器在 Windows 使用 `-X utf8`，不要为默认 GBK 误报转换项目文件。
- PowerShell ScriptProperty 异常可能表现为 null；先读取一次并拒绝 null/0，再转换或据缺失 key 清状态。
- 有序字典按键访问或先 JSON 回读为对象；显示投影为空不代表原始回执丢失。

## 发布与维护

- [三渠道发布核对](../../three-channel-publication/SKILL.md)：同次 main 原包、不可变版本、现有凭据、本人验证码及实际公开下载 SHA。
- 测试、CI、文档维护不单独发版；本轮运行修复合成一个用户可感知版本。审核接收不计公开完成。
- 缺商店凭据的绿色 CI 不证明商店上线；不创建凭据、不扩大权限、不重复上传审核中版本。
- README/CODEX 保持用户说明和一屏状态；run ID、资产 ID、原始哈希及完整诊断只放 verification 文档或测试根目录。
- 修改前保留 Git 状态和原编码；原工作区已有改动先备份核对，再按明确授权整合，不覆盖同事修改。
- 当前目标成功完成回执与随后无当前目标的查询分开判断，不因后者为空重新启动已完成目标。

- 冷路径取证尽量只用核心运行时；禁止命令模块自动加载的真实控制能揭露多余 Join-Path/JSON 依赖，但不能替代原超时现场的因果证明。
- 大矩阵按完整样本联合判断两引擎及包；日志归档客户端超限时改逐 job REST，保留原失败和请求错误，不能把诊断/控制次数计作完整连绿。
