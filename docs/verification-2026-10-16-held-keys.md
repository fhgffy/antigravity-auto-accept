# 5.3.7：普通键长按时暂缓物理审批（2026-10-16）

证据等级：已读源码、已跑无桌面输入回归；本记录不代表 Chrome 原生持续输入验收。

## 问题与修复

物理回退的 AreInputKeysReleased 仅检查鼠标键和修饰键。普通键已按住、尚未重复或输入时间戳未变化时，Click 仍可能执行 SendInput。浏览器窄菜单已有全键检查，未覆盖这一物理回退入口。

共享按键检查现在读取虚拟键 1 至 255 的高位。在 Click 入口和提交批次前都让出已按住的键；现有 500ms 空闲阈值、前台和窗口归属、审批身份、指针及输入时间戳保护保持。松开按键并恢复空闲后，原扫描循环继续处理，无需新增设置。

- 新增 28 案例：Enter、字母、功能键、方向键、数字键盘、Tab、空格；分别在入口已按住和最终身份核验期间按下，光标恢复开关各覆盖一次。
- 修复前 28 案例均错误发送输入，PS7 回归 exit 1。修复后同一回归 125 检查通过，exit 0。
- 完整 npm test 通过；PS5 x86 单独通过 125 项鼠标检查。PS5 x64 与 PS7 x64 由完整套件覆盖。
- 独立只读复核执行全部 255 个虚拟键、两个时点及两种恢复配置，共 1020 个拒绝案例，另两个无按键正例；1022 检查通过。
- 测试保留生产 C# Click 和实际保护逻辑，只替换已有原生依赖边界；没有发送真实桌面输入。
- UTF-8 无 BOM、CRLF、PowerShell AST 与 diff 检查通过。
