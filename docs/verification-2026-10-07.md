## 修复与旧版对照

- 多窗口公平性：实际扫描尾段的三轮计数由首窗 3、次窗 0，变为首窗 2、次窗 1。
- 首窗控件树失效：旧版阻断后续窗口；当前实现将异常限制在窗口或按钮内。
- 宿主查询中按钮改名、禁用或离屏：最终复核必须阻止旧按钮继续被调用。
- Invoke 已产生副作用再报错：旧版可能再物理点击；当前实现不再物理重试，并将动作尝试计入冷却。
- 最后一次坐标查询期间父进程退出：当前实现跳过物理动作。
- 通知/自动启动偏好变化不重启正在运行的扫描器；真正的扫描参数变化继续按最新配置重启。
- 主动 OFF 取消等待授信后的自动启动；输出管道错误可恢复，退出后输出只能作为带退出标识的诊断，不能更新新实例 READY/WAITING。
- managed UIAutomationClient 没有原代码引用的 LegacyIAccessiblePattern。移除无效分支后仍要求能读取 SelectionItem 的选中状态；未知状态零提交。本版本没有引入 native COM 的 Legacy 桥。

以上使用实际生产函数及扫描尾段；外部窗口、控件、鼠标只替换为固定计数桩。不能把这些回归写成每种布局全部实机通过。

## 可复现验证

开发入口为 npm ci、npm test、npm run package，然后通过 tests/validate-vsix.ps1 核对最终 VSIX。默认测试包含编译、类型检查、严格 UTF-8 无 BOM/CRLF、清单与锁文件、生命周期、两引擎按钮自测和扫描回归、真正的并发进程接管。

并发测试每轮创建 5 个测试宿主和 5 个测试扫描器，使用唯一互斥名及空目标进程集合；两轮逐次正常释放、异常终止和接管。默认双引擎实跑输出：

```text
___SCANNER_CONCURRENCY_TEST_DONE___:passed=22:rounds=2:engines=2
```

GitHub CI 将 Windows PowerShell 5.1 与 PowerShell 7 分成独立 job，要求实际主版本正确，再分别运行单引擎扫描和并发测试。打包 job 等待两者通过；对 VSIX 文件名单、清单、发布身份和运行文件字节做核对，随后保存 VSIX 及 SHA-256 artifact。配置包含超时、同分支并发取消和手动触发。

测试入口按 UTF-8 读取，并给 Parser.ParseInput 传绝对文件名以保留 PSScriptRoot；普通 ScriptBlock.Create 会丢失此上下文。打包检查的负向对照破坏临时包内 extension.js 后实际非零退出。
