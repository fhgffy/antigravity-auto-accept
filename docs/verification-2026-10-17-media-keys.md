# 5.3.8：媒体键状态导致浏览器审批永久等待（2026-10-17）

## 已跑本机诊断

Antigravity IDE 原会话在窄侧栏显示 `Agent needs permission to act on example.com`，右侧菜单横向裁切。5.3.7 已识别正确卡片及 More actions，实际提供 ScrollItem 和 ExpandCollapse 模式，但一直在前台输入守卫返回失败，未进入展开动作。

临时本机诊断区分了前台、长按与输入时间检查，确认持续阻塞来自 `0xB0`。微软[虚拟键表](https://learn.microsoft.com/en-us/windows/win32/inputdev/virtual-key-codes)将其定义为 VK_MEDIA_NEXT_TRACK。此处证明系统持续返回媒体键按下状态；未验证该状态来自哪个硬件、驱动或软件，不归因于键盘故障。

候选修复仅跳过 `0xAD..0xB3` 的七个音量及媒体播放键，菜单和物理回退使用同一输入键检查。其余键、500ms 空闲时间、输入戳变化、前台和审批身份复核保持生效。正式日志只保留固定拒绝原因；临时控制键诊断已移除。

00:25:09 重启原插件扫描器，00:25:13 原输出通道记录 `Auto-accepted (Invoke): "Allow Once (browser domain permission)"`。侧栏尺寸未改变，没有人工点击权限按钮，没有选择 Always Allow。随后窗口清单中的浏览器标题为 Example Domain。原 IDE 被最小化，恢复遇到用户输入提示后停止抢占；因此本次没有把最终 Agent 回复或完整浏览器任务完成计作已验证。

## 已跑离线回归

生产 MouseHelper 方法只替换原生依赖，测试本身不发送桌面输入。Windows PowerShell 5.1 和 PowerShell 7 各通过 188 项，包括：

- 七个媒体键分别在开始前及最终校验期间保持按下，测试指针恢复开关两种配置，共28个实际物理控制流用例。
- 媒体键与鼠标、字母、修饰、浏览器导航、启动键和 Unicode 输入键并存时，物理批准仍为零。
- 前台菜单守卫检查媒体键下的499ms/500ms边界；在第二、第三轮键状态重读中加入字母键仍拒绝。
- 原有前台改变、输入戳变化、查询失败、遮挡和审批失效检查继续运行。

本报告的本机证据来自安装目录内的候选扫描器；发行 VSIX 的归档校验、CI 和商店公开状态分别核验，不能由这一次通过推断所有窗口、所有应用输入或全部 IDE 版本均兼容。
