## 旧版失败对照

- 将生产 C# Click 方法的 native 系统调用和 Sleep 替换成内存输入模型，保留方法本体：30ms 内用户移动时方法返回 false，却把指针拉回旧位置；50ms 按住及20ms恢复等待期间发生移动，也被覆盖。
- 入场左键已按住时，旧方法仍发送 Down/Up，测试中的用户按住状态被松开；Shift 已按住仍批准。
- 窗口归属查询期间发生指针移动，旧方法会在新位置注入；同窗口布局将原 Accept 坐标换为 Reject，顶层窗口和 PID 保持不变仍会点击。
- 真实测试子进程只打印 FAKE-DOWN/FAKE-UP、不注入桌面；保留原生产方法50ms等待，收到Down后强杀子进程，未输出Up。托管 finally 不能保证在宿主强制终止时配对释放。
- 浏览器生产函数的 UIA 树桩在宿主查询或滚动期间改变目标文案、替换同文案 runtime ID、替换卡片身份、转移 Allow Once 父链或移走旧菜单项。旧源码在7类场景仍批准旧动作；精确关联且用户已展开菜单的第8类场景则无法自动批准。PS5/PS7均复现8项失败。

以上输入模型不触碰桌面，不能描述成真实鼠标竞态已在每种应用中重现。原生 API 返回、窗口和树查询之间仍有时序空档，无法把轮询校验称为系统级原子操作。
