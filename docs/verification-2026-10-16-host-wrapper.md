# 宿主测试超时诊断验证（2026-10-16）

本轮修复测试与 CI 的诊断缺口。插件运行代码和版本保持 5.3.7；已公开的 GitHub、Open VSX、Marketplace 原包不替换。

## 问题与边界

5.3.7 主分支 CI 的首次运行中，x86 宿主测试超过原有 45 秒限制。旧包装器先抛异常，随后停止子进程，却没有保留异步收集的 stdout/stderr。这不能用于定位卡在启动、编译还是断言阶段。

现在超时后只停止包装器持有的子进程，最多等待退出 5 秒，再分别等待两条输出流 1 秒；诊断明确记录退出与读取是否完成。停止、读取、释放或输出诊断失败均不得覆盖原超时。成功路径的退出码、严格 stderr 和 DONE 检查保持。

这项修复没有证明原来偶发启动超时的根因已经解决，也没有增加重试或延长原 45 秒限制。

## 已跑验证

- 红灯：真实包装器管理独占 C# 夹具，夹具写入中文 stdout、stderr 和 DONE 后继续停滞。旧代码约 47 秒后失败，因缺失超时诊断使新增测试失败；另外四个边界通过。
- 最终完整 `npm test` 退出 0。新增回归在 Windows PowerShell 5.1 与 PowerShell 7 各验证超时、成功、stderr、退出码 7、缺少 DONE，共 10 项通过。超时即使提前输出 DONE 仍失败，且夹具确认退出。
- 原有仓库检查、发布回归、自检、扩展生命周期、扫描器、宿主身份、鼠标输入和并发接管测试通过。生产输入 API 未被这些测试调用。
- 独立审查发现外层 65 秒看门狗提前结束包装器时可能遗留夹具。3 秒故障注入复现该问题后，回归入口增加登记 PID 与独占 EXE 完整路径核验，再通过持有的 Process 对象停止夹具；失败时保留原异常和无法回收的旁证。
- 独立复验直接执行最终测试文件，仅注入外层 3 秒限制：原 ETIMEDOUT 仍令测试退出 1，夹具确认退出、独占目录已删除。没有复制清理实现，没有改动包装器原 45 秒阈值。
- 源文件严格 UTF-8、无 BOM、CRLF；PowerShell 解析、CJS 语法和 diff 空白检查通过。
